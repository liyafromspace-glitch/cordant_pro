# Cordant prototype UI audit

Source-only audit of `src/components.css`, `src/app.js`, and `src/ui-library.js`. No implementation files were changed. Findings are based on source behavior; no browser or viewport run was performed.

## Findings

1. **Evidence tooltips clip at the ends of the lineage.** `.evidence-pop` is a fixed 220px box centered on each `.lineage-node` (`src/components.css:51-53`). The first and last nodes can push it beyond the lineage/card bounds, especially in the horizontally scrolling mobile lineage. The tooltip also sits above the node and can overlap the card heading. `body.show-evidence` reveals every tooltip simultaneously, guaranteeing overlap. Add edge-aware positioning (first node left-align, last right-align), constrain width with `max-width: calc(100vw - 24px)`, and show one selected tooltip at a time. For mobile, use a tap/focus disclosure that stays within the scroll container or a viewport-positioned popover.

2. **Lineage evidence has no keyboard entry point.** `.lineage-node` is a `div` with `cursor:default`, and the tooltip only opens on `:hover` or the global `body.show-evidence` class (`src/app.js:39-42`, `src/components.css:37,53`). Keyboard and touch users cannot open a node-specific preview; the `E` shortcut opens all of them. Make nodes buttons (or focusable controls) with accessible names, open the same single preview on `:focus-visible`/activation, and close it on Escape. Make the `E` shortcut ignore editable controls and preserve selection.

3. **Timeline keyboard scrubbing loses focus.** `#scrubber`'s `input` handler calls `render()` (`src/app.js:155`), which replaces all of `#app` (`src/app.js:135-139`). Each arrow-key update therefore destroys the focused range input. Update the stateful timeline/lineage DOM in place, or defer rendering until `change`; preserve slider focus and value while scrubbing.

4. **The desktop lineage is likely too compressed at common laptop widths.** `.incident-grid` has a `minmax(360px, .9fr)` side column and a nine-column lineage with fixed 28/40px connector tracks (`src/components.css:33,36`). It only switches to one column at `1050px`; in the interval just above that, the left card has little usable width and node text wraps tightly. Raise the collapse breakpoint based on the minimum usable lineage width, or give `.lineage` a deliberate min-width with a contained horizontal scroller at that breakpoint.

5. **Mobile progress labels disappear and the rail becomes ambiguous.** At `max-width:1050px`, `.progress-step span:last-child { display:none }` removes all five step names (`src/components.css:114`); the fixed bottom rail then exposes only identical unlabeled dots. Keep compact labels (short names or an accessible horizontal scroller) and add `aria-current="step"` to the active button in `renderShell` (`src/ui-library.js:18`).

6. **The progress rail and toast can collide on short screens.** `.progress-rail` is fixed at the bottom with `z-index:45`, while `#toast-region` is fixed at `bottom:88px; z-index:80` (`src/components.css:91,113`). A toast can cover the content just above the rail, and content can be obscured when the viewport is short or zoomed. Make the rail wrap/scroll at narrow widths and place toasts in a safe-area-aware live region above it with bounded width and stacking.

7. **Approval controls have inconsistent and unsafe activation paths.** `.hold` approves after a 1.1s pointer timer, but Enter/Space approves immediately (`src/app.js:167`). Pointer cancellation/lost capture does not cancel the timer, and the handler does not prevent Space's default behavior. Preserve the hold rule for keyboard (or provide a separate explicit confirmation), handle `pointercancel`/blur/Escape, and announce completion. The click path also does not distinguish approver identities in state: `state.approvals` is only two booleans, so it cannot enforce two distinct people or show who attested (`src/app.js:6-12,167`). Store identity/time/hash per attestation and block duplicate identity.

8. **Changing the package input does not clear existing approval state.** The `#authority-input` input handler sets `packageReady=false` but leaves `state.approvals` untouched (`src/app.js:165`). If a user returns from approval and edits, the next approval view can still show prior attestations; `#handoff` is disabled based on those booleans (`src/app.js:109`). Clear approvals and regenerate/review the package hash on every material edit; gate handoff against approvals for the current hash.

9. **Verification timer can be started again after each rerender.** Clicking `#start-verification` starts an interval then renders; the button is recreated while `state.executing` is true and still rendered because its condition is `!state.executing&&!state.complete` (actually hidden while executing), so duplicate start is avoided in the UI. However the simulated sequence has no failure/cancel path and labels itself “Finalized” when the local counter reaches five (`src/app.js:117-118,169`). Keep this as an explicitly simulated state, and provide pending/failed/unknown outcomes if the prototype represents a workflow; do not imply independently verified chain finality from a timer alone.

10. **Clickable portfolio rows are not keyboard-operable controls.** `tbody tr[data-view]` receives a click listener but is not focusable or semantic navigation (`src/app.js:131,154`); hover is its only interaction styling (`src/components.css:112`). Put a real link/button in the incident cell (or make each row keyboard-focusable with Enter/Space handlers), add `:focus-visible`, and avoid assigning a no-op `data-view="portfolio"` to the other rows.

11. **Several visible controls are inert.** Header Search/Profile, “Export evidence”, and the “Open source evidence ↗” underlines have no action handlers (`src/ui-library.js:18`, `src/app.js:74,131,153-170`). Hide them until functional or provide an explicit disabled state/action; an underlined source label should be a real link/button.

12. **Hover-only feedback is missing for claims and lineage.** `.claim` highlights linked lineage nodes only through `mouseenter`/`mouseleave`; it has no `focus` equivalent (`src/app.js:157-160`). Add keyboard focus/activation to claims and mirror hover highlighting with `:focus-within` or focus handlers. The visible focus rule in `tokens.css` helps only controls that are actually focusable.

## Most useful fixes first

Fix single-tooltip placement/selection and keyboard access, then preserve focus during timeline updates and repair the approval invalidation/identity model. Those changes address the reported clipping/overlap and the most consequential interaction regressions. Follow with responsive progress labels and semantic keyboard access for portfolio rows.
